# CellKG

An ontology-grounded, RNA-aware **property graph of the human cell**, hosted in a local Neo4j
instance and reproducible end to end from public biological sources. CellKG integrates the human
gene/RNA catalogue with the cell's compartment system, its biological processes and molecular
functions, and a gene–gene molecular-interaction layer into a single, densely connected graph
suitable for context-aware Cypher querying and knowledge-graph-embedding link prediction.

The graph comprises **39,352 nodes** and **336,452 relationships**. It was built as the course
project for *MDS7205 — Grafos de Conocimiento*, Magíster en Data Science, Universidad de Chile.

---

## What the graph models

CellKG layers five biological knowledge sources into one Neo4j property graph. Genes and RNAs are
typed by Ensembl biotype; cellular compartments are grounded in the Gene Ontology Cellular Component
(GO CC) hierarchy; and every relationship carries provenance and, where applicable, an
evidence-reliability or confidence property.

### Node labels

| Label | Key | Meaning | Count |
|---|---|---|---|
| `Gene` (+ RNA-biotype sub-label, e.g. `ProteinCoding`, `LncRNA`) | `ensembl_id` | human gene / RNA | 19,702 |
| `Protein` | `uniprot_id` | protein product | 19,212 |
| `CellularComponent` (22 curated anchors also carry `Organelle`) | `go_id` | GO cellular compartment | 52 |
| `BiologicalProcess` | `term` | HPA biological process | 232 |
| `MolecularFunction` | `term` | HPA molecular function | 129 |
| `Chromosome` | `name` | chromosome 1–22, X, Y, MT | 25 |

### Relationship types

| Relationship | From → To | Key properties |
|---|---|---|
| `CONTAINS` | Chromosome → Gene | `source` |
| `LOCATED_IN` | Gene → Organelle | `reliability`, `hpa_term` |
| `PARTICIPATES_IN` | Gene → BiologicalProcess | `source` |
| `HAS_FUNCTION` | Gene → MolecularFunction | `source` |
| `ENCODES` | Gene → Protein | `source` |
| `INTERACTS_WITH` | Gene → Gene | `score` (STRING combined_score, ≥ 700) |
| `PART_OF` | Organelle/CC → Organelle/CC | containment / GO part_of |
| `SUBCLASS_OF` | CellularComponent → CellularComponent | GO is_a |
| `ADJACENT_TO` | Organelle → Organelle | curated adjacency |

The resulting network is a single connected component (100 % of nodes), densely cyclic (circuit
rank ≈ 297,082, driven by the STRING interaction layer), with a recursively-grounded GO Cellular
Component DAG of longest-path depth 8.

## Knowledge sources

| Source | Release | Contribution |
|---|---|---|
| **Ensembl** (*Homo sapiens*, GRCh38.p14) | GTF | gene catalogue, RNA biotypes, coordinates; `Gene`, `Chromosome`, `CONTAINS` |
| **Human Protein Atlas** | full JSON | subcellular localization, biological process, molecular function, UniProt xref; `LOCATED_IN`, `PARTICIPATES_IN`, `HAS_FUNCTION`, `ENCODES` |
| **Gene Ontology** | `go-basic.obo` | Cellular Component grounding + is_a/part_of DAG |
| **STRING** v12.0 (9606) | protein links + info + aliases | high-confidence interaction network; `INTERACTS_WITH` |
| **Curated organelle ontology** | shipped CSVs | 22 GO-CC-anchored compartments + containment + adjacency crosswalks |

## Repository layout

The repository tracks the **code and curated inputs** needed to rebuild the graph. Heavy and derived
artifacts (the downloaded sources, the generated import CSVs, the Neo4j server, the `.venv`, and the
reports directory) are intentionally excluded via `.gitignore` and regenerated by the pipeline.

```
cellkg/
├── Makefile                 # orchestration: setup|organelles|fetch|build|load|validate|query|ml|all|gnn-*
├── requirements.txt / .lock # Python dependencies (pinned in .lock)
├── src/                     # ETL + database helpers
│   ├── make_organelles.py   # curated 22-organelle CSVs
│   ├── fetch_sources.py     # download the public sources
│   ├── build_ensembl.py     # genes from the Ensembl GTF
│   ├── build_hpa.py         # localization / process / function / protein from HPA
│   ├── build_go.py          # GO Cellular Component subgraph (obonet)
│   ├── build_string.py      # STRING interactions (ENSP→ENSG, score ≥ 700)
│   ├── emit_csvs.py         # assemble neo4j-admin CSVs, drop isolated genes
│   ├── load.sh              # bulk import + start server + apply DDL + verify
│   ├── apply_ddl_verify.py  # constraints/indexes + count verification
│   ├── validate.py          # characterization + acceptance gates
│   ├── run_competency.py    # execute the 10 competency questions
│   └── cellkg_db.py         # .env-driven Neo4j driver helper
├── ml/run_pykeen.py         # TransE + RotatE link prediction
├── ml/gnn/                  # Track 2: GraphSAGE + representativeness-weighted evaluation harness
├── tests/                   # pytest (fast tests; `-m slow` needs trained artifacts)
├── cypher/                  # DDL constraints, competency + presentation queries
└── data/raw/organelles/     # curated organelle inputs (only tracked data)
```

## Reproducing the graph

The entire build is driven by the `Makefile`. Each target prints its own progress.

```zsh
make setup        # create the venv and install dependencies (once)
make organelles   # write the 22-organelle curated CSVs into data/raw/organelles/
make fetch        # download the public sources (Ensembl, HPA, GO, STRING)
make build        # ETL: raw sources -> neo4j-admin CSVs in data/import/
make load         # bulk-import into Neo4j, start the server, apply constraints, verify counts
make validate     # graph characterization + interesting-network acceptance gates
make query        # run the 10 competency questions
make ml           # train PyKEEN TransE + RotatE link-prediction models
make all          # the full chain, end to end
```

Inputs are version-pinned (`data/raw/SHA256SUMS`, `requirements.lock`) and the ML split uses a fixed
seed, so results are reproducible.

### Prerequisites

- **Java 21** — required by Neo4j 5.26.
- **Python 3.12** — the `Makefile` builds a `--system-site-packages` venv that reuses base
  `torch`/`pandas`/`pyarrow`/`networkx` and installs `neo4j`, `pykeen`, and `obonet` on top.
- **Neo4j Community 5.26** — a local server (no Docker or internet required to run it).

## Using the graph

Once loaded, the graph is reachable four ways:

- **Neo4j Browser** — the visual interface at `http://localhost:7474`, connecting over
  `bolt://localhost:7687` as user `neo4j`.
- **cypher-shell** — the terminal client, for one-off queries or running a whole `.cypher` file.
- **Python driver** — `src/cellkg_db.py` wraps an `.env`-driven Neo4j session for analysis and ML.
- **Precomputed reports** — read the results of the last run without opening the database.

A first query to try in the Browser:

```cypher
MATCH p = (:Gene {symbol:'TP53'})-[r:INTERACTS_WITH]-(:Gene)
WHERE r.score >= 950
RETURN p LIMIT 40;
```

The `cypher/competency_all.cypher` file holds ten well-commented competency questions that move from
simple gene lookups through recursive ontology traversal, multi-hop functional reasoning, topological
similarity, and cross-layer path finding.

## Machine learning

`ml/run_pykeen.py` trains **TransE** and **RotatE** knowledge-graph embeddings (via PyKEEN) and
evaluates gene→organelle **link prediction**. It reports MRR and Hits@{1,3,10} overall and on the
localization task against random and popularity baselines, and emits ranked *novel* gene→organelle
predictions that can be used to prioritize experiments.

```zsh
PYTHONPATH=src ./.venv/bin/python ml/run_pykeen.py --epochs 60 --dim 256 --interact-sample 100000
```

### Graph neural network track

`ml/gnn/` adds a heterogeneous **GraphSAGE** model (PyTorch Geometric) that encodes each gene from its attributes and its interaction, process, function, chromosome and ontology neighbourhoods, and scores all 22 organelles at once with masked-label training and a logit-adjusted loss. Every method — popularity prior, neighbour vote, label propagation, a feature-only perceptron, re-trained TransE/RotatE and GraphSAGE — is scored by one harness on identical held-out edges: the exact replay of the PyKEEN split (the published degree, TransE and RotatE numbers are reproduced exactly) and a 5-fold inductive gene split. Alongside micro MRR/Hits@k the harness reports macro and representativeness-weighted MRR, per-organelle AP/AUROC, rare-tail aggregates and gene-level bootstrap intervals. GraphSAGE is the first model of the project to beat the popularity prior on the published metric; results are in `reports/gnn/comparison_table.md` and §8 of the technical report.

```zsh
make gnn-setup    # PyTorch Geometric + iterative-stratification in the venv
make gnn          # graph, splits, KGE re-training, baselines, GraphSAGE, ablations, evaluation, comparison
make gnn-test     # fast tests
make gnn-fast     # smoke run of the whole track into reports/gnn_fast/
```

Neo4j is needed once, by `make gnn-splits`, to export the triples in store order for the exact replay; the export is persisted under `reports/gnn/export/` and every later stage runs offline on CPU.

## Credentials and ports

Both endpoints bind to `127.0.0.1` only. The local user is `neo4j`; the password is generated at
first load and stored in the project's untracked `.env`.

| What | Address | Use |
|---|---|---|
| Neo4j Browser (visual UI) | `http://localhost:7474` | open in a web browser |
| Bolt (drivers, cypher-shell) | `bolt://localhost:7687` | programmatic access — not a web URL |

A local operator's guide (server control, credential reset, restoring from the archived dump, and a
full capabilities walkthrough) lives in `GUIDE.md`.
